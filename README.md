# Lab 06: Category-Partition ба PICT

**Оюутны нэр:** Т.Мөнхцэцэн  
**Оюутны код:** B232270025

## 1. Ажлын орчин

- **Тестийн загвар боловсруулах арга:** Category-Partition
- **Pairwise тест үүсгэх хэрэгсэл:** Microsoft PICT
- **Шалгах функц:** `POST /transfer`

## Зорилго

Энэ лабораторийн ажлаар банкны шилжүүлгийн функцэд Category-Partition аргаар сонголт, төлөөлөх утга, хязгаарлалт болон спецификаци боловсруулна. Мөн Microsoft PICT ашиглан pairwise болон 3-way covering array үүсгэж, гараар боловсруулсан тестийн загвартай харьцуулна.

# Хэсэг A. Category-Partition

## A1. Сонголт ба төлөөлөх утгууд

Банкны шилжүүлгийн функцийн `from`, `to`, `amount`, `currency` гэсэн дөрвөн оролтын параметрийг үндэслэн Category тодорхойлов.

| Category     | Сонголт     | Төлөөлөх утга                                                         | Тайлбар                                |
| ------------ | ----------- | --------------------------------------------------------------------- | -------------------------------------- |
| From account | Valid       | Байгаа, царцаагаагүй данс                                             | Шилжүүлэг эхлүүлэх боломжтой           |
| From account | Frozen      | Байгаа боловч царцаасан данс                                          | Шилжүүлэг хийх эрхгүй                  |
| From account | Missing     | Байхгүй дансны ID                                                     | Эхлэх данс олдохгүй                    |
| To account   | Valid       | Байгаа, `from`-оос өөр данс                                           | Хүлээн авагч хүчинтэй                  |
| To account   | Missing     | Байхгүй дансны ID                                                     | Хүлээн авагч олдохгүй                  |
| To account   | SameAsFrom  | `from`-той ижил дансны ID                                             | Өөр рүүгээ шилжүүлэх оролдлого         |
| Amount       | Normal      | Эерэг, үлдэгдэл болон өдрийн лимитэд багтах дүн                       | Амжилттай шилжүүлэх боломжтой          |
| Amount       | Zero        | `0`                                                                   | `amount ≤ 0` нөхцөлийн алдааг төлөөлнө |
| Amount       | OverBalance | Хөрвүүлсний дараах дүн үлдэгдлээс их боловч өдрийн лимитэд багтах дүн | Хүрэлцэхгүй үлдэгдэл                   |
| Amount       | OverLimit   | Хөрвүүлсний дараах дүн өдрийн лимитээс их боловч үлдэгдэлд багтах дүн | Өдрийн лимит хэтэрсэн                  |
| Currency     | Same        | Дансны валюттай ижил                                                  | Хөрвүүлэлт шаардлагагүй                |
| Currency     | Different   | Дансны валютаас өөр                                                   | Ханшийн хөрвүүлэлт шаардлагатай        |

**Шалгах функц:** `POST /transfer`

**Оролтын параметрүүд:** `from`, `to`, `amount`, `currency`.

**Далд орчны сонголт:** Өдрийн лимитийн үлдэгдэл, дансны бодит үлдэгдэл, дансны царцаасан төлөв болон валютын ханш нь хүсэлтийн шууд параметр биш боловч тестийн үр дүнд нөлөөлнө. Эдгээрийг тусдаа PICT Category болгоогүй; харин тестийн setup буюу урьдчилсан нөхцөлөөр тодорхойлно.

`amount` нь `currency`-ийн валютаар өгөгдөнө. Үлдэгдэл болон өдрийн лимитийг валют хөрвүүлсний дараах дүнгээр шалгана.

## A2. Хязгаарлалтууд

Нэг хүсэлтэд хэд хэдэн алдаа зэрэг илэрч болох тул хүлээгдэх үр дүнг тодорхойлохын тулд дараах давуу эрэмбийг сонгов:

1. `ERROR_NO_FROM`
2. `ERROR_FROZEN`
3. `ERROR_NO_TO`
4. `ERROR_SAME_ACCOUNT`
5. `ERROR_BAD_AMOUNT`
6. `ERROR_INSUFFICIENT`
7. `ERROR_LIMIT`

Энэ лабораторийн загварт эхлэх дансны алдааг эхэлж, дараа нь хүлээн авагчийн данс болон дүнгийн алдааг шалгахаар үзэв. Энэ нь тодорхойлолтод заагаагүй алдааны дарааллыг тестийн oracle боловсруулах зорилгоор тогтоосон таамаглал бөгөөд бодит хэрэгжүүлэлтийн баталгаа биш.

### A2.1. Утгуудын тэмдэглэгээ ба үндэслэл

| Category     | Төлөөлөх утга | Тэмдэглэгээ        | Үндэслэл                                                                                                        |
| ------------ | ------------- | ------------------ | --------------------------------------------------------------------------------------------------------------- |
| From account | Valid         | `[property]`       | Эхлэх данс байгаа, царцаагаагүй тул бусад нөхцөл хүчинтэй үед шилжүүлэг хийх боломжтой.                         |
| From account | Frozen        | `[ERROR]`          | Царцаасан данснаас шилжүүлэг хийх боломжгүй тул `ERROR_FROZEN` хүлээнэ.                                         |
| From account | Missing       | `[ERROR]`          | Эхлэх данс байхгүй бол `ERROR_NO_FROM` хүлээнэ.                                                                 |
| To account   | Valid         | `[property]`       | Хүлээн авагчийн данс байгаа бөгөөд эхлэх данснаас өөр байна.                                                    |
| To account   | Missing       | `[ERROR]`          | Хүлээн авагчийн данс байхгүй бол `ERROR_NO_TO` хүлээнэ.                                                         |
| To account   | SameAsFrom    | `[ERROR] [SINGLE]` | Эхлэх болон хүлээн авагчийн данс ижил бол `ERROR_SAME_ACCOUNT` хүлээнэ; энэ онцгой нөхцөлийг тусгайлан шалгана. |
| Amount       | Normal        | `[property]`       | Эерэг дүн нь хөрвүүлсний дараа үлдэгдэл болон өдрийн лимитэд багтана.                                           |
| Amount       | Zero          | `[ERROR]`          | Тэг дүн нь эерэг биш тул `ERROR_BAD_AMOUNT` хүлээнэ.                                                            |
| Amount       | OverBalance   | `[ERROR]`          | Хөрвүүлсний дараах дүн үлдэгдлээс их бол `ERROR_INSUFFICIENT` хүлээнэ.                                          |
| Amount       | OverLimit     | `[ERROR]`          | Хөрвүүлсний дараах дүн өдрийн лимитээс их бол `ERROR_LIMIT` хүлээнэ.                                            |
| Currency     | Same          | `[property]`       | Валют ижил үед хөрвүүлэлт хийх шаардлагагүй.                                                                    |
| Currency     | Different     | `[IF/property]`    | Валют өөр үед ханшийн хөрвүүлэлт хийж, хөрвүүлсний дараах дүнгээр үлдэгдэл болон лимитийг шалгана.              |

**Тэмдэглэгээний тайлбар**

- `[ERROR]`: алдааны нөхцөлийг төлөөлөх сонголт.
- `[SINGLE]`: бусад алдаатай хослуулахгүйгээр тусгайлан шалгах шаардлагатай нөхцөл; дангаараа PICT-ийн хязгаарлалт биш.
- `[IF/property]`: бусад сонголт эсвэл орчны нөхцөлөөс хамаарч тайлбарлагдах сонголт.
- `[property]`: бусад нөхцөл хүчинтэй үед хэвийн ажиллагааг төлөөлөх сонголт.

### A2.2. Хязгаарлалтын дүрмүүд

PICT загварт дараах хязгаарлалтыг хэрэглэв:

```text
IF [From] = "Missing" THEN [Amount] = "Normal";
IF [To] = "Missing" THEN [Amount] = "Normal";
```

Эхний дүрэм нь `From = Missing` үед `Amount`-ийн бусад утгуудтай хослуулахгүй. Хоёр дахь дүрэм нь `To = Missing` үед `Amount`-ийн бусад утгуудтай хослуулахгүй.

Эдгээр нь лабораторийн загварын сонголт юм. Бодит системд эдгээр нөхцөлийг заавал ингэж хязгаарлах ёстой гэсэн үг биш.

`Daily limit`-ийг тусдаа Category болгоогүй. Өдрийн лимитийн нөхцөлийг `Normal`, `OverBalance`, `OverLimit` сонголтуудын төлөөлөх утга болон тестийн setup-аар тодорхойлно.

### A2.3. Бүрэн олонлог ба хязгаарлалтын дараах тооцоо

Үндсэн дөрвөн параметрийн утгын тоо:

| Category | Утгын тоо |
| -------- | --------: |
| From     |         3 |
| To       |         3 |
| Amount   |         4 |
| Currency |         2 |

**Хязгаарлалтгүй бүрэн олонлог:**

\[
N = 3 \times 3 \times 4 \times 2 = 72
\]

`From = Missing` үед `Amount = Normal` байх ёстой. `Amount`-ийн бусад 3 утга тус бүр `To`-гийн 3 утга, `Currency`-гийн 2 утгатай хосолж болох тул хасагдах тохиргооны тоо:

\[
3 \times 3 \times 2 = 18
\]

Үүнтэй адил `To = Missing` үед `Amount`-ийн бусад 3 утгыг хасна:

\[
3 \times 3 \times 2 = 18
\]

`From = Missing` болон `To = Missing` зэрэг тохиолдсон үед ижил тохиргоонууд хоёр удаа хасагдсан тул давхардлыг буцаан нэмнэ:

\[
3 \times 2 = 6
\]

Иймээс хоёр IF хязгаарлалтын дараах боломжит бүрэн тохиргооны тоо:

\[
M = 72 - 18 - 18 + 6 = 42
\]

**Үр дүн: 72 → 42 боломжит бүрэн тохиргоо.**

Энэ тооцоо нь зөвхөн хоёр IF хязгаарлалтын нөлөөг харуулна. `[ERROR]` болон `[SINGLE]` тэмдэглэгээг тусдаа хязгаарлалт болгон хэрэгжүүлээгүй тул тооцоонд оруулаагүй.

PICT-ийн `Combinations` нь бүрэн тохиргооны тоотой адил үзүүлэлт биш бөгөөд B хэсэгт тусад нь тайлбарлав.

### A3.1. Тестийн орчны урьдчилсан нөхцөл

- `Valid` эхлэх болон хүлээн авагчийн данс бодитоор байна.
- `Frozen` данс байгаа боловч царцаасан байна.
- `Missing` нь өгөгдлийн санд байхгүй дансны ID-г төлөөлнө.
- `SameAsFrom` үед эхлэх болон хүлээн авагчийн ID ижил байна.
- `Normal` үед шилжүүлэх дүн эерэг бөгөөд хөрвүүлсний дараа үлдэгдэл, өдрийн лимитэд багтана.
- `OverBalance` үед хөрвүүлсний дараах дүн үлдэгдлээс их боловч өдрийн лимитээс хэтрээгүй байна.
- `OverLimit` үед хөрвүүлсний дараах дүн өдрийн лимитээс их боловч үлдэгдэлд багтсан байна.
- `Different` үед валютын ханшийн хөрвүүлэлт хийгдэнэ.
- Олон алдаа зэрэг илэрвэл A2 хэсэгт тодорхойлсон давуу эрэмбээр хүлээгдэх үр дүнг сонгоно.
- Өдрийн лимитийн тестэд тухайн дансны өмнөх шилжүүлэг болон үлдсэн лимитийг урьдчилан тохируулна.

# Хэсэг B. Microsoft PICT

## B1. PICT хэрэгсэл бүтээж суулгах

PICT-ийн эх кодыг лабораторийн репозитороос гадуур `~/tools/pict` хавтаст татаж авч, CMake ашиглан бүтээв. Ингэснээр PICT-ийн эх код болон `build/` хавтас лабораторийн репозиторт орохгүй.

Ашигласан командууд:

```bash
sudo apt update
sudo apt install -y git cmake g++ make

mkdir -p ~/tools
cd ~/tools
git clone https://github.com/microsoft/pict
cd pict

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j4
sudo cp build/cli/pict /usr/local/bin/
pict
```

PICT-ийн commit болон хэрэглээний зааврын нотолгоог `results/pict-build.txt` файлд хадгалсан. Энэ файлд commit hash, огноо болон PICT-ийн Usage мөрүүд байна.

## B2. Browser загвар: pairwise ба 3-way

`browser.model` загварын параметрүүд:

```text
Allow: Allow, Restrict, Block
Cookies: Allow, Restrict, Block
Popups: Yes, No
Addons: Yes, No
Attacks: Yes, No
Forgeries: Yes, No
```

Бүрэн олонлогийн тохиргооны тоо:

\[
3 \times 3 \times 2^4 = 144
\]

PICT-ийг санамсаргүй seed ашиглахгүйгээр ажиллуулсан:

```bash
pict browser.model > results/browser-2way.txt
pict browser.model /o:3 > results/browser-3way.txt
```

Мөрийн тоог эхний header мөрийг хасаж тоолов.

| Үзүүлэлт                  | 2-way | 3-way |
| ------------------------- | ----: | ----: |
| Үүссэн тестийн мөр        |    10 |    20 |
| Бүрэн олонлогийн тохиргоо |   144 |   144 |

2-way горимд 10 мөр үүссэн нь лекц дээр гараар гаргасан 9 мөрөөс нэгээр олон байна. PICT нь greedy алгоритм ашигладаг тул pairwise хамралтыг хангаж болох ч хамгийн цөөн мөртэй шийдлийг заавал гаргахгүй. 3-way горимд 20 мөр үүссэн бөгөөд энэ нь бүх 144 тохиргоог нэг бүрчлэн шалгахын оронд гурван параметрийн түвшний хамралтыг хангах зорилготой.

## B3. Шилжүүлгийн PICT загварууд

### B3.1. Хязгаарлалтгүй загвар — `transfer-nc.model`

```text
From: Valid, Frozen, Missing
To: Valid, Missing, SameAsFrom
Amount: Zero, Normal, OverBalance, OverLimit
Currency: Same, Different
```

Энэ загварт хязгаарлалт байхгүй. Тиймээс нэг мөрөнд олон алдааны нөхцөл зэрэг орж болох бөгөөд хүлээгдэх үр дүнг тодорхойлохдоо A2-ын давуу эрэмбийг ашиглана.

### B3.2. Хязгаарлалттай загвар — `transfer.model`

```text
From: Valid, Frozen, Missing
To: Valid, Missing, SameAsFrom
Amount: Zero, Normal, OverBalance, OverLimit
Currency: Same, Different

IF [From] = "Missing" THEN [Amount] = "Normal";
IF [To] = "Missing" THEN [Amount] = "Normal";
```

Энэ загвар нь `From` эсвэл `To` байхгүй үед `Amount`-ийн алдаатай утгуудтай хослол үүсгэхгүй.

### B3.3. Сөрөг утгатай загвар — `transfer-neg.model`

```text
From: Valid, ~Frozen, ~Missing
To: Valid, ~Missing, ~SameAsFrom
Amount: Normal, ~Zero, ~OverBalance, ~OverLimit
Currency: Same, Different
```

PICT-ийн `~` тэмдэглэгээ нь тухайн утгыг сөрөг утга гэж тэмдэглэнэ. Үүний үр дүнд нэг мөрөнд хамгийн ихдээ нэг сөрөг утга орно. Энэ нь Category-Partition загварын `[ERROR]` тэмдэглэгээтэй төстэй зорилготой боловч хоёр тэмдэглэгээ нь өөр өөр хэрэгслийн дүрэм юм.

### B3.4. Загваруудын бодит үр дүнгийн харьцуулалт

Загвар бүрийг дараах командуудаар ажиллуулсан:

```bash
pict transfer-nc.model > results/transfer-nc.txt
pict transfer.model > results/transfer.txt
pict transfer-neg.model > results/transfer-neg.txt
```

Мөрийн тоог эхний header мөрийг хасаж тоолов.

| Үзүүлэлт          | `transfer-nc.model` | `transfer.model` | `transfer-neg.model` |
| ----------------- | ------------------: | ---------------: | -------------------: |
| Хязгаарлалт       |             Байхгүй |       2 IF дүрэм |     `~` сөрөг утгууд |
| Тестийн мөр       |                  13 |               12 |                   16 |
| Happy path мөр    |                   1 |                0 |                    2 |
| Нэг алдаатай мөр  |                   1 |                3 |                   14 |
| Олон алдаатай мөр |                  11 |                9 |                    0 |

Happy path гэдэг нь `From = Valid`, `To = Valid`, `Amount = Normal` бөгөөд бусад алдааны нөхцөлгүй мөр юм. Алдааны тоог загварын сонголтуудаар тооцсон бөгөөд давхар алдаатай мөрийн хүлээгдэх oracle нь A2-ын давуу эрэмбээс хамаарна.

Хязгаарлалтгүй загварт 13 тест гарсан боловч 11 мөрөнд олон алдаа давхар орсон. Хязгаарлалттай загварт 12 тест гарсан ч бусад алдаанууд давхар орж болох тул IF дүрэм нь бүх error masking-ийг арилгахгүй. Сөрөг утгатай загварт 16 тест гарч, нэг мөрөнд хамгийн ихдээ нэг сөрөг утга орсон бөгөөд хоёр happy path мөр үүссэн.

`~` тэмдэглэгээ нь нэг мөрөнд хэд хэдэн алдааны утга давхар орохоос сэргийлдэг учраас A2-ын IF хязгаарлалтуудын хэрэгцээг бууруулна. Гэхдээ энэ нь A2-ын бүх логик хязгаарлалттай яг адил биш: `~` нь дансны төлөвийн бизнес дүрэм эсвэл далд орчны нөхцөлийг өөрөө баталгаажуулахгүй.

### B3.5. PICT статистик: `transfer.model`

`transfer.model` загварыг 2-way болон 3-way горимоор ажиллуулсан:

```bash
pict transfer.model /s 2>&1 | tee results/transfer-2way-stats.txt
pict transfer.model /o:3 /s 2>&1 | tee results/transfer-3way-stats.txt
```

PICT-ийн бодит статистик:

**2-way**

```text
Combinations:   47
Generated tests:12
Generation time:0:00:00
```

**3-way**

```text
Combinations:   75
Generated tests:26
Generation time:0:00:00
```

| Үзүүлэлт                            |    2-way |    3-way |
| ----------------------------------- | -------: | -------: |
| Параметрийн тоо                     |        4 |        4 |
| Хязгаарлалтгүй бүрэн тохиргооны тоо |       72 |       72 |
| PICT-ийн `Combinations`             |       47 |       75 |
| Үүссэн тестийн мөр                  |       12 |       26 |
| Үүсгэлтийн хугацаа                  | 0 секунд | 0 секунд |

`Combinations` нь PICT-ийн статистикт тайлагнасан комбинацийн тоо бөгөөд бүрэн тохиргооны тоо биш. `Generated tests` нь бодитоор үүссэн тестийн мөрийн тоо юм.

### B3.6. PICT-ийн гаралтаас сонгосон тест кейсүүд

Доорх кейсүүд нь PICT-ийн гаралтаас сонгосон загварын жишээнүүд бөгөөд API дээр ажиллуулж баталгаажуулсан үр дүн биш. Дансны ID болон мөнгөн дүн нь тестийн орчинд тохируулах жишээ утгууд юм.

#### TC-P1 — Happy path

**Эх үүсвэр:** `transfer-nc.model`-ийн хүчинтэй мөр.

**Setup**

- `ACC-001`: хүчинтэй, царцаагаагүй MNT данс, үлдэгдэл 500,000 MNT.
- `ACC-002`: хүчинтэй, царцаагаагүй MNT данс.
- Өдрийн лимитэд 100 MNT-ээс их үлдэгдэлтэй.

**Оролт**

```json
{
  "from": "ACC-001",
  "to": "ACC-002",
  "amount": 100,
  "currency": "MNT"
}
```

**Oracle:** HTTP `201`, `{"result":"OK"}`.

#### TC-P2 — Нэг алдаа: Amount Zero

**Эх үүсвэр:** `transfer-neg.model`-ийн `~Zero` утгатай мөр.

**Setup**

- `ACC-001` болон `ACC-002` нь хүчинтэй, царцаагаагүй, өөр дансууд.
- Валютын хөрвүүлэлт хийх шаардлагагүй эсвэл ханшийн тохиргоо хүчинтэй байна.

**Оролт**

```json
{
  "from": "ACC-001",
  "to": "ACC-002",
  "amount": 0,
  "currency": "MNT"
}
```

**Oracle:** HTTP `200`, `{"result":"ERROR_BAD_AMOUNT"}`.

#### TC-P3 — Давхар алдаа: Missing From, SameAsFrom, Zero

**Эх үүсвэр:** `transfer-nc.model`-ийн дараах мөр:

```text
Missing  SameAsFrom  Zero  Same
```

**Setup**

- `ACC-999` өгөгдлийн санд байхгүй.
- `from` болон `to` талбарт ижил байхгүй ID өгнө.
- `amount` нь тэг байна.
- Олон алдаа зэрэг илэрвэл A2-ын давуу эрэмбийг хэрэглэнэ.

**Оролт**

```json
{
  "from": "ACC-999",
  "to": "ACC-999",
  "amount": 0,
  "currency": "MNT"
}
```

**Oracle:** HTTP `200`, `{"result":"ERROR_NO_FROM"}`. Энэ нь `ERROR_NO_FROM` нь `ERROR_SAME_ACCOUNT` болон `ERROR_BAD_AMOUNT`-аас түрүүлж шалгагдана гэсэн лабораторийн таамаглалд үндэслэнэ.

# Хэсэг C. Category-Partition ба PICT-ийн харьцуулалт

## C1. Харьцуулалтын хүснэгт

| Шалгуур                 | Category-Partition                                           | PICT                                                                        |
| ----------------------- | ------------------------------------------------------------ | --------------------------------------------------------------------------- |
| Загвар боловсруулах     | Ангилал, сонголт, төлөөлөх утгыг гараар тодорхойлно          | Параметр, утга, хязгаарлалтаас тест үүсгэнэ                                 |
| Гол зорилго             | Чухал нөхцөл, алдааны төрлийг тодорхойлох                    | Параметрийн хослолын хамралтыг системтэй хангах                             |
| Давуу тал               | Хүлээгдэх үр дүн, бизнесийн утгыг ойлгомжтой тайлбарлана     | Олон параметрийн хослолыг автоматаар үүсгэнэ                                |
| Сул тал                 | Олон хослолыг гараар боловсруулахад цаг орно                 | Загвар дутуу бол чухал нөхцөл орхигдож болно                                |
| Алдааны семантик        | Алдааны төрөл болон давуу эрэмбийг тодорхойлоход тохиромжтой | Олон алдаа давхардахаас сэргийлэхийн тулд `~` болон IF хязгаарлалт хэрэгтэй |
| Энэ лабораторийн үр дүн | 16 төлөвлөсөн спецификаци                                    | Browser: 10/20; transfer: 13/12/16 тест                                     |

## C2. Дүгнэлт

Энэ лабораторийн ажлаар банкны шилжүүлгийн `POST /transfer` функцийн дөрвөн оролтын параметрийг Category-Partition аргаар ангилж, хүчинтэй болон алдаатай утгуудыг тодорхойлсон. Мөн олон алдаа зэрэг илэрсэн үед хүлээгдэх үр дүнг сонгох давуу эрэмбийг тестийн загварын таамаглал болгон тогтоосон. Category-Partition нь алдааны утга, бизнесийн нөхцөл болон oracle-ийг ойлгомжтой тодорхойлоход илүү тохиромжтой. PICT нь параметрийн хослолуудыг автоматаар үүсгэж, pairwise болон 3-way хамралтыг системтэй шалгахад тусалдаг. Browser загварт 2-way горимд 10, 3-way горимд 20 тест үүссэн бөгөөд pairwise үр дүн лекцийн гараар боловсруулсан 9 мөрөөс нэгээр олон байв. Transfer загваруудад хязгаарлалтгүй хувилбарт 13, IF хязгаарлалттай хувилбарт 12, сөрөг утгатай хувилбарт 16 тест үүссэн. `~` тэмдэглэгээ нь нэг мөрөнд олон сөрөг утга давхар орохоос сэргийлдэг боловч бизнесийн бүх хязгаарлалтыг автоматаар баталгаажуулахгүй. Хамгийн их бодол шаардсан алхам нь давхар алдааны үед хүлээгдэх үр дүнг тодорхойлох, мөн дансны үлдэгдэл ба өдрийн лимитийг тестийн урьдчилсан нөхцөлөөр зөв загварчлах байв. Иймээс Category-Partition болон PICT-ийг хамтад нь ашиглах нь алдааны семантик болон хосын хамралтыг илүү бүрэн авч үзэх боломж олгодог.
