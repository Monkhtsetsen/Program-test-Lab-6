# Lab 06: Category-Partition ба PICT

**Оюутны нэр:** Т.Мөнхцэцэн  
**Оюутны код:** B232270025

## 1. Ажлын орчин

- Тестийн загвар боловсруулах арга: Category-Partition
- Pairwise тест үүсгэх хэрэгсэл: Microsoft PICT
- Шалгах функц: `POST /transfer`

## Зорилго

Энэ лабораторийн ажлаар банкны шилжүүлгийн функцэд Category-Partition аргаар тестийн сонголт, төлөөлөх утга, хязгаарлалт болон спецификаци боловсруулна. Мөн Microsoft PICT ашиглан pairwise covering array үүсгэж, гараар боловсруулсан тестийн загвартай харьцуулна.

# Хэсэг A. Category-Partition

## A1. Сонголт ба төлөөлөх утгууд

Банкны шилжүүлгийн функцийн оролтын параметрүүд болох `from`, `to`, `amount`, `currency`-ийг үндэслэн дөрвөн Category тодорхойлов.

| Category     | Сонголт     | Төлөөлөх утга                                                         | Тайлбар                        |
| ------------ | ----------- | --------------------------------------------------------------------- | ------------------------------ |
| From account | Valid       | Байгаа, царцаагаагүй данс                                             | Шилжүүлэг эхлүүлэх боломжтой   |
| From account | Frozen      | Байгаа боловч царцаасан данс                                          | Шилжүүлэг хийх эрхгүй          |
| From account | Missing     | Байхгүй дансны ID                                                     | Эхлэх данс олдохгүй            |
| To account   | Valid       | Байгаа, `from`-оос өөр данс                                           | Хүлээн авагч хүчинтэй          |
| To account   | Missing     | Байхгүй дансны ID                                                     | Хүлээн авагч олдохгүй          |
| To account   | SameAsFrom  | `from`-той ижил дансны ID                                             | Өөр рүүгээ шилжүүлэх оролдлого |
| Amount       | Normal      | Эерэг, үлдэгдэл болон өдрийн лимитэд багтах дүн                       | Амжилттай шилжүүлэх боломжтой  |
| Amount       | Zero        | `0`                                                                   | Эерэг биш дүн                  |
| Amount       | Negative    | `0`-ээс бага дүн                                                      | Хүчинтэй бус дүн               |
| Amount       | OverBalance | Шилжүүлсний дараах дүн үлдэгдлээс их боловч өдрийн лимитэд багтах дүн | Хүрэлцэхгүй үлдэгдэл           |
| Amount       | OverLimit   | Шилжүүлсний дараах дүн өдрийн лимитээс их боловч үлдэгдэлд багтах дүн | Өдрийн лимит хэтэрсэн          |
| Currency     | Same        | Дансны валюттай ижил                                                  | Хөрвүүлэлт шаардлагагүй        |
| Currency     | Different   | Дансны валютаас өөр                                                   | Хөрвүүлэлт шаардлагатай        |

**Шалгах функц:** `POST /transfer`

**Оролтын параметрүүд:** `from`, `to`, `amount`, `currency`.

**Өдрийн лимитийн нөхцөл:** Өдрийн лимит нь API хүсэлтийн тусдаа оролтын параметр биш, харин дансны төлөв болон тухайн өдөр хийгдсэн өмнөх шилжүүлгүүдээс хамаарах нөхцөл юм. Иймээс `Daily limit`-ийг PICT загварт тусдаа Category болгохгүй. Харин `Normal`, `OverBalance`, `OverLimit` сонголтуудын төлөөлөх утгыг тодорхойлох болон тестийн орчны урьдчилсан нөхцөлд ашиглана.

## A2. Хязгаарлалтууд

Олон алдаа зэрэг илэрсэн үед хүлээгдэх үр дүнг нэг мөр тодорхойлохын тулд дараах давуу эрэмбийг сонгов:

1. `ERROR_NO_FROM`
2. `ERROR_FROZEN`
3. `ERROR_NO_TO`
4. `ERROR_SAME_ACCOUNT`
5. `ERROR_BAD_AMOUNT`
6. `ERROR_INSUFFICIENT`
7. `ERROR_LIMIT`

Энэ эрэмбээр эхэлж шалгагдах нөхцөлийн алдааг тухайн хүсэлтийн хүлээгдэх үр дүн гэж үзнэ. Энэ нь лабораторийн тестийн загвар гаргахад зориулсан таамаглал бөгөөд бодит системийн хэрэгжүүлэлт заавал ийм дараалалтай гэсэн баталгаа биш.

### A2.1. Утгуудын тэмдэглэгээ ба үндэслэл

| Category     | Төлөөлөх утга | Тэмдэглэгээ        | Үндэслэл                                                                                   |
| ------------ | ------------- | ------------------ | ------------------------------------------------------------------------------------------ |
| From account | Valid         | `[property]`       | Эхлэх данс байгаа бөгөөд царцаагаагүй үед шилжүүлэг хийх боломжтой.                        |
| From account | Frozen        | `[ERROR]`          | Царцаасан данснаас шилжүүлэг хийх боломжгүй тул `ERROR_FROZEN` үүснэ.                      |
| From account | Missing       | `[ERROR]`          | Эхлэх данс байхгүй бол `ERROR_NO_FROM` үүснэ.                                              |
| To account   | Valid         | `[property]`       | Хүлээн авагчийн данс байгаа бөгөөд эхлэх данснаас өөр байна.                               |
| To account   | Missing       | `[ERROR]`          | Хүлээн авагчийн данс байхгүй бол `ERROR_NO_TO` үүснэ.                                      |
| To account   | SameAsFrom    | `[ERROR] [SINGLE]` | Эхлэх болон хүлээн авагчийн данс ижил бол `ERROR_SAME_ACCOUNT` үүснэ.                      |
| Amount       | Normal        | `[property]`       | Дүн эерэг бөгөөд үлдэгдэл, өдрийн лимитэд багтана.                                         |
| Amount       | Zero          | `[ERROR]`          | Тэг дүн нь эерэг биш тул `ERROR_BAD_AMOUNT` үүснэ.                                         |
| Amount       | Negative      | `[ERROR]`          | Сөрөг дүн нь хүчинтэй шилжүүлгийн дүн биш тул `ERROR_BAD_AMOUNT` үүснэ.                    |
| Amount       | OverBalance   | `[ERROR]`          | Шилжүүлэх дүн үлдэгдлээс их бол `ERROR_INSUFFICIENT` үүснэ.                                |
| Amount       | OverLimit     | `[ERROR]`          | Шилжүүлэх дүн өдрийн лимитээс их бол `ERROR_LIMIT` үүснэ.                                  |
| Currency     | Same          | `[property]`       | Дансны валюттай ижил үед хөрвүүлэлт хийх шаардлагагүй.                                     |
| Currency     | Different     | `[IF/property]`    | Валют өөр үед хөрвүүлэлт хийгдэж, хөрвүүлсний дараах дүнгээр үлдэгдэл ба лимитийг шалгана. |

**Тэмдэглэгээний тайлбар**

- `[ERROR]`: тухайн утга алдааны нөхцөлийг төлөөлнө.
- `[SINGLE]`: тухайн сонголтыг тусгайлан шалгах шаардлагатайг тэмдэглэнэ. Энэ тэмдэглэгээ дангаараа хослол хасах дүрэм болохгүй; хэрэглэж буй аргачлалын дагуу тодорхой хязгаарлалт шаардлагатай.
- `[IF/property]`: өөр сонголт эсвэл орчны нөхцөлөөс хамаарах шинжийг илэрхийлнэ.
- `[property]`: бусад нөхцөл хүчинтэй үед хэвийн ажиллагааг төлөөлөх сонголт.

### A2.2. Хязгаарлалтын дүрмүүд

Олон алдаатай оролтын хүлээгдэх үр дүнг тодорхойлохын тулд A2 хэсэгт тодорхойлсон давуу эрэмбийг ашиглана:

`ERROR_NO_FROM` > `ERROR_FROZEN` > `ERROR_NO_TO` > `ERROR_SAME_ACCOUNT` > `ERROR_BAD_AMOUNT` > `ERROR_INSUFFICIENT` > `ERROR_LIMIT`

PICT загварт хэрэглэх хязгаарлалт:

```text
IF [From] = "Missing" THEN [Amount] = "Normal";
IF [To] = "Missing" THEN [Amount] = "Normal";
```

Эхний дүрмийн дагуу эхлэх данс байхгүй үед дүнгийн алдаатай утгуудтай хослуулахгүй.

Хоёр дахь дүрмийн дагуу хүлээн авагчийн данс байхгүй үед дүнгийн алдаатай утгуудтай хослуулахгүй.

Эдгээр нь лабораторийн тестийн загварын сонголт бөгөөд бодит системийн хэрэгжүүлэлтийн баталгаа биш.

`Daily limit`-ийг тусдаа Category болгохгүй тул өдрийн лимитийн нөхцөлд зориулсан нэмэлт PICT параметр эсвэл IF дүрэм оруулахгүй. Лимитийн нөхцөлийг `Amount`-ийн сонголт болон тестийн орчны урьдчилсан нөхцөлөөр тодорхойлно.

### A2.3. Бүрэн олонлог ба хязгаарлалтын дараах тооцоо

Үндсэн дөрвөн параметрийн сонголтын тоо:

| Category | Утгын тоо |
| -------- | --------: |
| From     |         3 |
| To       |         3 |
| Amount   |         5 |
| Currency |         2 |

Бүрэн олонлогийн хэмжээ:

\[
N = 3 \times 3 \times 5 \times 2 = 90
\]

Эхний IF дүрмийн дагуу `From = Missing` үед `Amount = Normal` байх ёстой.

`From = Missing` үед `Amount`-ийн бусад дөрвөн утга тус бүр хасагдана. `To` нь 3, `Currency` нь 2 боломжтой тул:

\[
4 \times 3 \times 2 = 24
\]

Хоёр дахь IF дүрмийн дагуу `To = Missing` үед `Amount = Normal` байх ёстой. Үүнтэй адил:

\[
4 \times 3 \times 2 = 24
\]

Гэхдээ `From = Missing` болон `To = Missing` зэрэг тохиолдсон хослолууд хоёр удаа хасагдсан тул давхардлыг буцаан нэмнэ. Энэ үед `Amount`-ийн 4 алдаатай утга, `Currency`-ийн 2 утга боломжтой:

\[
4 \times 2 = 8
\]

Иймээс хоёр IF хязгаарлалтын дараах олонлог:

\[
M = 90 - 24 - 24 + 8 = 50
\]

**Үр дүн: 90 → 50 боломжит хослол.**

Энэ тооцоо нь зөвхөн дээрх хоёр IF дүрмийн нөлөөг харуулна. `[ERROR]` болон `[SINGLE]` тэмдэглэгээг нэмэлт хязгаарлалт болгон тодорхойлоогүй тул уг тооцоонд оруулаагүй.

Мөн 50 нь хязгаарлалтын дараах боломжит бүрэн хослолын тоо болохоос PICT-ийн pairwise тестийн гаралтын мөрийн тоо биш.

Дараах 16 спецификаци нь амжилттай шилжүүлэг, алдааны ангилал тус бүр, валютын хөрвүүлэлт, тусгай дансны нөхцөл болон олон алдаа зэрэг илэрсэн тохиолдлыг хамарна.

**Тайлбар:** Хүлээгдэх HTTP статус болон JSON хариуг лабораторийн загварын дагуу тодорхойлсон. Бодит API-ийн хариу эдгээртэй нийцэж байгаа эсэхийг тест ажиллуулж баталгаажуулна.

### A3.1. Тестийн орчны урьдчилсан нөхцөл

- `Valid` эхлэх болон хүлээн авагчийн данс бодитоор байна.
- `Frozen` данс байгаа боловч царцаасан байна.
- `Missing` утга нь өгөгдлийн санд байхгүй дансны ID-г төлөөлнө.
- `SameAsFrom` үед эхлэх болон хүлээн авагчийн ID ижил байна.
- `Normal` үед шилжүүлэх дүн эерэг бөгөөд хөрвүүлсний дараах дүн үлдэгдэл болон өдрийн лимитэд багтана.
- `OverBalance` үед хөрвүүлсний дараах дүн үлдэгдлээс их боловч өдрийн лимитээс хэтрээгүй байна.
- `OverLimit` үед хөрвүүлсний дараах дүн өдрийн лимитээс их боловч үлдэгдэлд багтсан байна.
- `Different` үед валютын ханшийн хөрвүүлэлт хийгдэнэ.
- Олон алдаа зэрэг илэрвэл A2 хэсэгт тодорхойлсон давуу эрэмбээр хүлээгдэх үр дүнг сонгоно.
- Өдрийн лимитийн тест хийхдээ тухайн дансны өмнөх шилжүүлгийн дүн болон үлдсэн лимитийг урьдчилан тохируулна.

Эдгээр нь тестийн загварын урьдчилсан нөхцөл юм. Бодит API дээр ажиллуулж баталгаажуулсан үр дүн гэж үзэхгүй.

# Хэсэг B. Microsoft PICT

## B1. PICT загварын файл

PICT загварт API-ийн дөрвөн оролтын параметрийг ашиглана. `Daily limit` нь хүсэлтийн тусдаа параметр биш тул загварт оруулахгүй.

`transfer_model.txt` нэртэй файл үүсгэж дараах агуулгыг оруулна:

```text
From: Valid, Frozen, Missing
To: Valid, Missing, SameAsFrom
Amount: Normal, Zero, Negative, OverBalance, OverLimit
Currency: Same, Different

IF [From] = "Missing" THEN [Amount] = "Normal";
IF [To] = "Missing" THEN [Amount] = "Normal";
```

## B2. PICT ажиллуулах

Linux (Ubuntu/WSL) терминал дээр PICT суусан бөгөөд ажиллах боломжтой гэж үзээд дараах командыг ажиллуулна.

```bash
pict transfer_model.txt > pict_results.txt
```

Энэ команд нь PICT-ээр үүсгэсэн pairwise тестийн үр дүнг `pict_results.txt` файлд хадгална.

Үр дүнг харахын тулд дараах командыг ашиглана:

```bash
cat pict_results.txt
```

Гаралтын хүснэгтийн эхний мөр нь параметрийн нэрс, дараагийн мөрүүд нь үүссэн тестийн тохиолдлууд байна.

**Анхаарах зүйл:** Хэрэв `pict: command not found` алдаа гарвал PICT суулгагдсан эсэх болон PATH тохиргоог шалгана. Мөн хязгаарлалтын синтакс буруу байвал PICT-ийн гаралтын алдаанд үндэслэн загварыг засна.

## B3. Pairwise тестийн үр дүнг үнэлэх

Pairwise тестийн зорилго нь параметрүүдийн бүх боломжит бүрэн хослолыг шалгах бус, харин параметрүүдийн бүх хүчинтэй хоёр утгат хослол дор хаяж нэг тестэд хамрагдсан эсэхийг хангахад оршино.

Энэ загварт дараах параметрийн хослолуудыг хамруулна:

- `From` ба `To`
- `From` ба `Amount`
- `From` ба `Currency`
- `To` ба `Amount`
- `To` ба `Currency`
- `Amount` ба `Currency`

Хязгаарлалтын улмаас боломжгүй болсон хослолуудыг pairwise хамрах хүрээний үнэлгээнд хүчинтэй хослол гэж тооцохгүй.

PICT-ийн бодит гаралтыг шалгахын тулд:

```bash
wc -l pict_results.txt
```

Энэ команд нийт мөрийн тоог харуулна. Эхний мөр нь баганын нэрс тул файл хоосон биш, гаралтын формат хүлээгдсэнтэй нийцэж байгаа нөхцөлд тестийн тохиолдлын тоог нийт мөрөөс нэгийг хасаж тооцно.

**Үнэлгээ:** PICT-ийн үүсгэсэн тестийн тохиолдлын тоо болон pairwise хамрах хүрээг бодит гаралтад үндэслэн тодорхойлно. Ажиллуулаагүй үр дүнг урьдчилан таамаглан бичихгүй.

# Хэсэг C. Гараар боловсруулсан тест ба PICT-ийн харьцуулалт

## C1. Харьцуулалтын хүснэгт

| Шалгуур                          | Category-Partition                                        | PICT                                                       |
| -------------------------------- | --------------------------------------------------------- | ---------------------------------------------------------- |
| Тестийн загвар боловсруулах арга | Ангилал, сонголт, төлөөлөх утгыг гараар тодорхойлно       | Параметр болон хязгаарлалтаас тест үүсгэнэ                 |
| Гол зорилго                      | Функцийн чухал нөхцөл, алдааг системтэй тодорхойлох       | Pairwise хамрах хүрээг хангах                              |
| Давуу тал                        | Тестийн зорилго, хүлээгдэх үр дүнг ойлгомжтой тайлбарлана | Олон параметрийн хослолыг автоматаар үүсгэнэ               |
| Сул тал                          | Бүх чухал хослолыг гараар сонгоход цаг орно               | Буруу эсвэл дутуу загвар өгвөл чухал нөхцөл орхигдож болно |

## C2. Дүгнэлт

Category-Partition аргаар банкны шилжүүлгийн функцийн дөрвөн оролтын параметрийг тодорхойлж, хүчинтэй болон алдаатай утгуудыг ангилсан. Мөн олон алдаа зэрэг илэрсэн үед хүлээгдэх үр дүнг сонгох давуу эрэмбэ болон PICT загварт хэрэглэх хязгаарлалтуудыг боловсруулсан.

PICT нь параметрүүдийн pairwise хослолыг автоматаар үүсгэж, гараар боловсруулсан тестийн загварыг нэмэлтээр шалгахад ашиглагдана. Хоёр аргыг хослуулснаар чухал алдааны нөхцөлийг зориудаар хамруулахын зэрэгцээ параметрүүдийн харилцан үйлчлэлийг илүү системтэй шалгах боломжтой.

Өдрийн лимитийг тусдаа Category болгохгүй, харин `Amount` сонголтуудын утга болон тестийн урьдчилсан нөхцөлөөр загварчилсан. Ингэснээр Category-Partition болон PICT загвар нь API-ийн дөрвөн оролтын параметртэй нийцэж байна.
